Sentinel gate / application layer

Кожен запит — чотири перевірки до Flask.

Greylist відсікає вже відомі атаки, WAF шукає сигнатури в path/query/body, Rate Limiter рахує ковзне вікно за IP, і лише після цього запит потрапляє до бізнес-логіки. Відповідь 403 або 429 формується до виконання маршруту.

Відповіді до маршруту

403 Forbidden

waf_blocked або ip_greylisted. IP додається до Greylist; наступні запити блокуються тим самим інтервалом.

429 Too Many Requests

rate_limited + Retry-After: N. Клієнт знає, коли безпечно повторити запит.

HTML-клієнт отримує стилізовану сторінку, API — JSON із error.code, rule та retry_after.

Sliding Window Log: чому не Fixed Window

t₀ t₀+30 с now t₀+60 с

Кожен запит — мітка часу в deque. На кожному кроці відкидаються мітки старші за window_seconds. Немає «скидання» на межі хвилини, тому немає подвійного сплеску 2 × limit, характерного для Fixed Window. Пам'ять на ключ обмежена самим лімітом; застарілі ключі прибираються за RATE_LIMIT_KEY_TTL_SECONDS, а max_keys захищає від Memory Exhaustion DoS.

Defense in Depth: WAF і Rate Limiter — активний периметр, але не заміна безпечному коду. Параметризовані SQL-запити, Jinja2 autoescape, Bleach-санітизація та CSP із ЛР №1–3 залишаються другими рівнями. Сигнатурний WAF має False Positives, тому виключення для лабораторних сторінок і журнал інцидентів дозволяють контрольовано налагоджувати правила.
