Client perimeter / defense in depth

Один запит — чотири незалежні бар'єри.

Кожен шар перевіряє дані окремо: навіть якщо один механізм буде вимкнено або обійдено, наступний не дасть payload перетворитися на виконуваний код, викрасти сесію або прочитати чужу відповідь API.

01 · INPUT

Санітизація

  • Bleach 6.4: tags=[], strip=True
  • Видалення <script>, on*, javascript:
  • Окремі правила для імені файлу та шляху
  • Запис у БД лише очищеного тексту
Stored XSS neutralized
→
02 · OUTPUT

Екранування

  • Jinja2 autoescape для HTML-контексту
  • escape_text() для не-HTML контекстів
  • Жодного |safe на користувацьких даних
  • Залишкові < стають &lt;
Reflected XSS neutralized
→
03 · BROWSER

Політика браузера

  • script-src 'self' без unsafe-inline
  • frame-ancestors 'none' + XFO: DENY
  • HSTS, nosniff, Referrer-Policy
  • report-uri /client-lab/csp-report
CSP enforcement
→
04 · SESSION

Сесія та Origin

  • HttpOnly — недоступно з JS
  • Secure — лише HTTPS / trustworthy localhost
  • SameSite=Strict — без cross-site відправки
  • CORS whitelist без *, Vary: Origin
CSRF / session theft blocked

Легенда

ВхідДані очищуються до збереження.
ВихідБудь-який залишок стає текстом.
БраузерПолітика виконується на клієнті.
СесіяCookie та Origin ізольовані.
Defense in Depth: жоден рівень не є єдиною точкою відмови. Санітизація захищає БД, autoescape — шаблон, CSP — браузер, а cookie/CORS — сесію та міжсайтову взаємодію. Компрометація одного шару не відкриває весь периметр.
