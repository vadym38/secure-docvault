JWT access flow.

Access Token перевіряється без звернення до сесії. Refresh Token зберігається в SQLite як одноразовий стан: після ротації старий jti отримує revoked_at, а повторне використання відкликає всю родину токенів.

Структура JWT: три частини через крапку

Header

{"alg":"HS256","typ":"JWT"}

Алгоритм і тип. Сервер дозволяє лише HS256.

Payload

{"sub":"1","username":"o.kravets","role":"user","type":"access","jti":"…","iat":…,"exp":…}

Клейми лише читаються; зміна робить підпис недійсним.

Signature

HMAC-SHA256(header.payload, secret)

Секрет ≥ 256 біт зберігається лише на сервері.

Контролі нейтралізації ризиків

  • TTL Access 15 хв, Refresh 7 діб; коротке вікно атаки.
  • ALG Явна заборона alg:none та підміни алгоритму.
  • REUSE Одноразовий Refresh; повтор відкликає family.
  • REVOKE Blacklist Access jti до його exp.
  • DATA У Payload немає паролів, хешів і зайвих PII.
